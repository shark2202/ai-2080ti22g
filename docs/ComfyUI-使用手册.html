ComfyUI 使用手册

适用机器：单卡 RTX 2080 Ti 22GB（Turing / sm_75） · ComfyUI v0.33.1 · MiniMax-H3（W4A8）+ SDXL

面向新手：每个场景都写清「需要哪些节点、怎么连、参数怎么改、改完大概多久」。

0 · 30 秒上手

先确认服务是活的，再跑一个最简单的文生图。

0.1 启动 ComfyUI（如果已经在跑，这步跳过）

bash /home/a/ai-work/minimax-h3-turing/scripts/h3_launch.local.sh

这个脚本是本机专用版，等价于在 /home/a/ai-work/ComfyUI 下执行：

TORCH_DISABLE_NATIVE_JIT=1 .venv/bin/python main.py \
  --listen 0.0.0.0 --port 8188 \
  --reserve-vram 2.5 --vram-headroom 0.5 --disable-pinned-memory
启动参数为什么是它（新手只要知道"别乱改"）
--reserve-vram 2.5永远给显卡留 2.5GB 不动，防止桌面共享显卡时黑屏（TDR）。生成 15 秒长片时改成 4。
--vram-headroom 0.5显存压力管理余量，同上，防爆。
--disable-pinned-memory本机 PyTorch 的 pinned memory 读文件路径会 OOM，直接关掉。
TORCH_DISABLE_NATIVE_JIT=1本机没装 python3.10-dev，Triton 现场编译会崩文本编码器。必须。
--listen 0.0.0.0⚠️ ComfyUI 没有任何鉴权。同网段任何人都能提交任务、读你的 output。想收紧：H3_LISTEN=127.0.0.1（只本机）或 H3_LISTEN=100.69.133.37（只走 tailscale）。

浏览器打开：http://127.0.0.1:8188（局域网机器用 http://<本机IP>:8188）。 日志在 /home/a/ai-work/ComfyUI/h3_server.log。

0.2 跑通第一个文生图（中文）

  1. 左侧工作流面板点 Workflow → 打开，选 /home/a/ai-work/ComfyUI/user/default/workflows/ui/zimage_turbo_t2i_api_ui.json（也可以直接把文件拖进网页）。
  2. 找到 CLIP Text Encode 节点，把 text 改成你想要的描述——中文直接写，例如 一位穿红色汉服的年轻女性站在竹林小径上，逆光，中国风。
  3. 点右上角 Queue Prompt（排队执行）。
  4. 右侧「队列」或 output/image/ 目录里出 PNG（约 8 秒）。
新手记住三件事
  • 节点＝一个方块，左边是输入、右边是输出，连线＝把上一个节点的输出插到下一个节点的输入。线连对了，节点框就会亮起来。
  • seed＝随机数。同一张图想再要一次"一模一样的"，就把 seed 设成 fixed；想换构图就点骰子换数字。
  • 输出永远在磁盘上：图片 ComfyUI/output/image/，视频 ComfyUI/output/video/。
想要英文写实风？用 ui/sdxl_juggernaut_t2i_api_ui.json（SDXL，30 步约 18 秒）—— 但它的 CLIP 只认英文，中文提示词基本不出效果。中文一律用 Z-Image（见 §3b）。

1 · 术语速查（白话版）

词一句话解释什么时候调它
节点 node一个功能方块。左边接输入、右边吐输出。搭工作流就是摆节点 + 连线。
latent图片被压缩后的"草稿"。采样全程在草稿上做，最后由 VAE 翻译成像素。一般不直接碰。
VAE解码器：latent → 图片/视频像素；反向就是"图片 → latent"。H3 有两个：视频 VAE、音频 VAE，别搞混。
seed随机种子。同 seed + 同参数 = 同一结果。想微调画面只改它。
steps迭代次数。越多细节越多，也越慢；到一定步数后不再变好。SDXL 25~35；H3 Turbo 4；H3 PDD 8。
cfg"多听话"。越高越死扣提示词，越高越容易过饱和、塑料感；太低则不听。SDXL 4~7；H3 固定 1.0（蒸馏已内置引导）。
sampler / scheduler去噪算法 + 步长排布。是一对，要配套用。SDXL 用 dpmpp_2m + karras；H3 Turbo 用 res_multistep + simple；H3 PDD 用 euler（不许换）。
denoise重绘强度。1.0 = 从零画；0.5 = 保留一半原图再改。img2img / 图生图用。只在"基于已有图修改"时用。
LoRA一小坨附加权重，给模型加风格或加速。H3 的 Turbo 4 步 LoRA、PDD 加速包都是它。
latent → 视频H3 一次采样同时出画面和声音（原生音轨）。音频长度和帧数绑死，见 §4.6。
帧数 lengthH3 按 17k+5 的网格对齐（124、209、362…）。24fps，124 帧 ≈ 5.2 秒。决定时长与耗时。

本机硬件天花板（先接受，再调参）
  • Turing 没有 BF16/FP8 张量核心，显存带宽只有 616 GB/s（3090 的 66%）。视频生成是访存密集型，比 3090 慢约 1.5 倍是物理事实，不是没调好。
  • 必须用 W4A8 权重。W4A4 的重建误差是 W4A8 的 18 倍，画面直接彩色撕裂。
  • SageAttention 2.2.0 + torch2.9 在 sm_75 上管线原生崩溃；T8 双时钟缓存官方判定 Turing 上不要用。加速只能走"LoRA/蒸馏 + 缓存近似"这条路。
  • 显存：H3 常驻约 19.5G / 22.5G，余量只有 2.5G 左右。同一张卡上不要同时跑本地 LLM，也不要开着 4K 视频浏览器。

3 · 场景一：文生图（SDXL / Juggernaut XL）

最快见效的场景，一分钟一张。用来出单帧插画、封面、参考图、给图生视频当首帧。

3.1 需要哪些节点（7 个）

① Load Checkpoint→ ② CLIP Text Encode（正）→ ⑤ KSampler→ ⑥ VAE Decode→ ⑦ Save Image
① Load Checkpoint→③ CLIP Text Encode（负）→⑤ KSampler
④ Empty Latent Image→⑤ KSampler
#节点（界面名）输入怎么接输出接到作用
①Load Checkpointckpt_name 选 Juggernaut-XL_v9_RunDiffusionPhoto_v2.safetensorsMODEL→⑤ / CLIP→②③ / VAE→⑥一次加载模型 + 文本编码器 + VAE。三个输出口都要用。
②CLIP Text Encode（正）clip ← ① 的 CLIPpositive → ⑤你的提示词。
③CLIP Text Encode（负）clip ← ① 的 CLIPnegative → ⑤不要出现的东西。
④Empty Latent Imagewidth / height / batch_sizelatent_image → ⑤画布大小和出几张。
⑤KSamplermodel←①，positive←②，negative←③，latent_image←④samples → ⑥主采样器，seed/steps/cfg 都在这。
⑥VAE Decodesamples←⑤，vae←①images → ⑦latent 解码成像素。
⑦Save Imageimages←⑥—存 PNG 到 output/image/。
照着连线看图：① 的三条线（MODEL / CLIP / VAE）是"公共管道"，②③ 是两根提示词线，④ 是画布线，⑤ 是核心，⑥⑦ 是尾巴。 缺任何一条线，对应节点框会变红，红框＝没接好。

3.2 默认参数

节点参数默认值为什么
④width / height1024 × 1024SDXL 原生分辨率。其它推荐：竖图 832×1216、横图 1216×832。
④batch_size1一次出几张，显存 ×N。本机建议 ≤ 4。
⑤seed3013（fixed）固定=可复现；点骰子=换构图。
⑤steps30SDXL 的甜点区 25~35。
⑤cfg5.0SDXL 的甜点区 4~7。
⑤sampler / schedulerdpmpp_2m / karras稳妥默认，别乱换。
⑤denoise1.0从零画。改成 0.4~0.6 就变成"改图"（需接 LoadImage）。
③负面提示词worst quality, low quality, jpeg artifacts, watermark, signature, text压画质噪点、水印、文字。

3.3 提示词怎么写

公式：主体 + 细节 + 风格 + 镜头/光线 + 质量词，用英文写（SDXL 对英文理解远好于中文）。

一只橘猫坐在木质窗台，午后侧逆光，毛发细节清晰，85mm 镜头浅景深，
写实摄影，胶片颗粒感，高细节，masterpiece

逗号分隔，越靠前权重越高（Juggernaut 对前半段更敏感）。

3.4 场景化调参：想改什么就动哪里

你想…动哪个参数调到注意
换个构图 / 换张脸⑤ seed点骰子，或改成 random其它一律不动，保证可比。
更听提示词⑤ cfg5 → 6.5>10 容易过饱和、边缘假。
细节更足⑤ steps30 → 40收益递减，40 以上基本白烧时间。
出 4 张挑一张④ batch_size1 → 4显存 ×4，1024² 下没问题。
改比例④ width/height832×1216 等别用 500 这种怪尺寸。
风格统一（系列图）② prompt 前缀固定同一前缀 + 换主体本机没有 SDXL 风格 LoRA，靠 prompt 维持一致性。
局部修图denoise 调低 + LoadImage0.4~0.6加 Load Image 节点替换 ④ 号 Empty Latent Image。
改分辨率重画denoise <1.0 + 改 width/height0.6~0.8经典 img2img 高清放大流程。
文生图的产线位置：它的三个出口分别是 ①当参考图给图生视频当首帧 ②当分镜草图 ③当缩略图/封面。 本机没有 SDXL 的 ControlNet、没有放大模型（upscale_models/ 是空的），所以 SDXL 这条线上"精准控姿态/高清放大"暂时做不了，别在这上面耗时间——这两件事走 §3b 的 Z-Image（它带 ControlNet Union）。

3b · 场景一续：中文出图（Z-Image-Turbo）

上一节的 SDXL 只认英文。短视频/漫剧剧本是中文的，用它等于每张图先翻译一遍。 Z-Image-Turbo 的文本编码器是 Qwen3-4B，中文直接写，而且 8 步出图、1024×1024 只要 8 秒。

先记住三件事 ① 中文出图走 Z-Image，英文写实走 SDXL，两条线不冲突，节点不通用。 ② Turbo 是蒸馏档：steps=8、cfg=1.0、不要写负面提示词（负向用 ConditioningZeroOut 置零）。 ③ 出图想给视频用，直接出 16:9（1024×576），H3 吃 640×352，比例对得上。

3b.1 节点（9 个，比 SDXL 多两个加载器）

① UNETLoader→ ⑤ ModelSamplingAuraFlow→ ⑧ KSampler→ ⑨ VAE Decode→ ⑩ Save Image
② CLIPLoader→ ⑥ CLIP Text Encode→⑧ KSampler ⑦ ConditioningZeroOut→⑧ KSampler
#节点（界面名）接什么作用
①Load Diffusion Modelunet_name = z_image_turbo_int8_convrot.safetensors出图主模型（Z-Image-Turbo，int8 权重）。
②Load CLIPclip_name = qwen_3_4b_fp8_mixed.safetensors，type = lumina2中文文本编码器（Qwen3-4B）。
③Load VAEvae_name = ae.safetensorsZ-Image 的 VAE。
④⑤ModelSamplingAuraFlowmodel ← ①，shift = 3.0官方指定的采样缩放，别改。
⑥CLIP Text Encode（正）clip ← ②，text 写中文正向条件。
⑦ConditioningZeroOutconditioning ← ⑥负向置零（Turbo 蒸馏档不要自己写负面提示词）。
⑧KSamplermodel ← ⑤，positive ← ⑥，negative ← ⑦，latent ← ⑦EmptyLatentImage主采样器。
⑨⑩VAE Decode → Save Imagevae ← ③解码存 PNG 到 output/image/。

3b.3 提示词怎么写（中文）

公式和 SDXL 一样：主体 + 细节 + 风格 + 镜头/光线 + 质量词，逗号分隔，越靠前权重越高。 中文直接写，不用翻译——实测"一只橘猫坐在木质窗台，午后侧逆光，毛发细节清晰，85mm 镜头浅景深，写实摄影" 出来的东西：橘猫、木质窗台、侧逆光、85mm 浅景深全部命中。

3b.4 图生图：同一角色换分镜（漫剧核心）

把 ③ 换成 Load Image → VAE Encode 顶替 EmptySD3LatentImage，denoise 调低， 就得到"保留角色、改姿势/换气氛"的图。denoise 是"改多少"旋钮：

denoise效果用在哪
0.55几乎只改光照，角色和构图全锁死同一张图换色调
0.6~0.75保留角色身份，换动作/气氛漫剧多分镜就用这档
0.9基本重画只借个大致色调
漫剧实测：先出 1 张角色定妆照 → 当参考图 → 分别喂 "低头看竹简""抬眼望向镜头外""转身走向竹林深处"三条提示词，denoise 0.7、换 seed， 出来的三张红汉服、发饰、竹林背景完全一致，只有动作和表情在变。

3b.5 ControlNet：精准控构图

接 Load Model Patch（选 Z-Image-Turbo-Fun-Controlnet-Union.safetensors） → Apply Z-Image Fun ControlNet（model ← ⑤，model_patch ← 补丁，vae ← ③，image ← 参考图）， 再把这个节点的 model 接到 KSampler。Union 一份权重支持 canny / depth / pose / hed / mlsd， 用界面里的 Detect Edges (Canny) 之类预处理节点出控制图即可。

3b.7 端到端：中文出图 → 图生视频（短视频主链路）

python3 /home/a/ai-work/minimax-h3-turing/scripts/zimage_to_h3.py \
  --prompt "一位穿红色汉服的年轻女性站在竹林小径上，逆光，中国风，水墨电影感" \
  --h3-prompt "女性缓缓转身，衣袖随风飘动，竹叶沙沙作响，镜头轻微推近"

实测：出图 8.3s → H3 图生视频 258.6s → 成片 ComfyUI/output/video/H3Lite_*.mp4（640×352 / 24fps / 5.17s / H.264 + 带音轨）。

两条出图线的选择
中文 / 漫剧 / 短视频 → Z-Image（本节）：中文直出、8 秒、图生图保角色、有 ControlNet。
英文写实封面 / 老素材 → SDXL（§3）：模型自带 VAE+CLIP 一个 checkpoint 全包，30 步但更稳，英文提示词表现细腻。
别混用节点：SDXL 的 checkpoint 不能直接喂 Z-Image 的 UNETLoader，反之亦然。

4 · 场景二：文生视频（MiniMax-H3）

本机最重、也最有价值的能力：一次出片，画面 + 同步音轨一起给。

先看这一条H3 有两套加速配方，只能用一套，不能叠加：
① Turbo 4 步（快，4 步，可复现）② PDD 8 步蒸馏（慢一倍，画质更好）。
PDD 路线禁止再挂 Turbo LoRA，也禁止再叠任何缓存节点（TeaCache / FirstBlockCache / T8），会直接报错。

4.1 公共骨架（15 个节点，两条配方共用）

① UNETLoader→⑤ MiniMaxH3SigmaShift→ 【配方分支】→⑦ BasicGuider→⑪ SamplerCustomAdvanced→ ⑫ VAEDecode→⑭ CreateVideo→⑮ SaveVideo
② ClipProjLoader→⑥ MiniMaxH3ImageToVideo→⑦ BasicGuider
⑥ MiniMaxH3ImageToVideo→⑪ SamplerCustomAdvanced（latent_image）
#节点关键参数（本机默认值）输出接到作用
①Load Diffusion Model（UNETLoader）minimax_h3_fl2va_pruned_w4a8_mixed_ax1y2jp.safetensors，weight_dtype=defaultMODEL → ⑤装 H3 主模型。

4.5 提示词三段式

【主体】一位穿黑色风衣的男人站在雨夜的霓虹街道
【动作/运镜】缓慢推近，手持轻微晃动，他抬头看向镜头
【环境/光线】霓虹反射在积水里，紫蓝色调，浅景深，背景人群虚化
【声音】雨声，远处车流，低沉的合成器氛围音
  • 英文写；主体写在最前面。
  • H3 原生出音轨，所以可以写"对白/音效/环境声"，写了就可能出对应声音。
  • 实测量级：Turbo 路线约 -14 dB、PDD 约 -15.9 dB，都不削波，但整体偏轻，成片建议过一遍响度/限制器。

4.6 耗时预期（本机实测，640×352 · 124 帧 · 24fps · 带音频）

场景配方耗时说明

4.7 帧数与音频的关系（重要）

音轨长度和帧数绑死。把原生帧数减半再插帧，画面时长能靠插帧拉回去，但音轨不会跟着变长（181 帧 → 音轨只剩 8 秒）。 → 需要原生音频的成片：老老实实生成足帧数，或"分段生成再拼接"。 → 后期配音覆盖的产线：可以减帧 + 插帧，省 47%~69% 时间。

6.1 让本机小模型写剧本（QwenScript 节点）

节点 Qwen3.8 Script (local LLM)（分类 MiniMax H3）：让本机的 Qwen3.8-9B 先写出提示词或整份逐镜剧本，再喂给 H3。

输入作用默认值

seed同 prompt 同 seed = 同一剧本3013

显存协议（这个节点存在的唯一理由）：22GB 卡上 LLM 与 H3 不可能同时驻留（LLM 6808 MiB + H3 峰值 18926 MiB > 22528 MiB）。 所以节点是串行：先卸载 ComfyUI 的模型 → 生成剧本 → 杀掉自己拉起的 LLM 进程 → 再让采样器跑。 用之前确保 llama-server 在 8080 上活着（ss -ltn | grep 8080）。

现成工作流：ui/h3_w4a8_t2v_qwenscript_api_ui.json。

6.2 缓存/加速节点在本机的状态表

节点状态怎么用禁忌
MiniMax H3 TeaCache已安装rel_l1_thresh 0.15（作者在 A100 上测到 −66%），start_step=2，end_step=-2，total_steps 要和采样步数一致会改轨迹 → 不可复现；PDD 路线禁止叠加
MiniMax H3 FirstBlockCache已安装mode 默认 H3 Fast（阈值 0.10，最多连命中 2 次）；要求保真用 H3 Safe同上；不要和别的缓存节点同时用
MiniMax H3 Block Cache (T8)已装但不推荐官方手册结论：Turing 上默认参数 0 命中、纯开销新手别用
EasyCache（ComfyUI 自带）判死短步数下语义崩坏别用
SageAttention不可用sm_75 上 Triton 编译失败 / 管线崩溃别用
PDD Acc LoRA推荐（画质档）nfe 8不要与 Turbo LoRA / 缓存节点叠加
加速的正确顺序：先换配方（PDD 8 步比 Turbo 4 步慢但画质好；Turbo 4 步最快）→ 再考虑缓存（省 30~45% 时间，但结果不可复现、轨迹会漂）。 成片用可复现的组合，草稿用带缓存的组合。

6.3 时长不够 → 插帧（RIFE）

  • 节点：ComfyUI 原生 FrameInterpolate；权重 rife_v4.flownet.pkl（24.6MB，HF MonsterMMORPG/Practical-RIFE）需自行下载到 models/frame_interpolation/（本机目前是空的，未安装）。
  • 实测：原生 362 帧 → 半帧 181 + RIFE 2x，时间 24.5 min → 13.0 min（−47%）；1/3 帧 121 + 3x → 7.5 min（−69%）。
  • 硬伤：H3 的原生音轨长度跟帧数绑死，帧数减一半音轨就缩一半。插帧只救画面不救声音。

6.4 清晰度不够 → 低分辨率生成 + 超分

  • 路线：640×352 生成（快）→ 抽帧 → RTX VSR（nvidia-vfx 轮子，Turing 可用，实测 ~47ms/帧）放大到 1080p → 合回视频。
  • 不要直接在工作流里把分辨率改到 1080p：每步时间会暴涨，显存也不够。
  • 本机 upscale_models/ / latent_upscale_models/ 都是空的 → ESRGAN 类图超分暂不可用；PDD 包自带的 MiniMax H3 AV Latent Upscale By 需要额外安装 Comfyui_Minimax_h3_latent_Upscaler 节点包和对应权重（未装）。

9.3 API 用法（可选）

提交一个工作流：

curl -s -X POST http://127.0.0.1:8188/prompt \
  -H 'Content-Type: application/json' \
  -d @workflow.json

api/ 目录里的文件里 "__PROMPT__" 是提示词占位符，"__H3_FIRST_FRAME__" 是首帧图片名（相对 ComfyUI/input/），"__IMAGE__" 是图生图的输入图名。 查队列：curl -s http://127.0.0.1:8188/queue；查历史：curl -s http://127.0.0.1:8188/history。

不想手工 curl 的话，仓库自带跑图脚本（/home/a/ai-work/minimax-h3-turing/scripts/）：

# 跑任意工作流（--prompt / --image / --seed 覆盖占位符）
python3 scripts/run_workflow.py workflows/api/zimage_turbo_t2i_api.json \
  --prompt "一位穿红色汉服的年轻女性站在竹林小径上"

# 中文出图 → H3 图生视频，一步到位
python3 scripts/zimage_to_h3.py --prompt "..." --h3-prompt "..."
