# 测评标准定位与对外可比性说明

> 结论先说：**model-eval 不是行业标准基准**。它是自建的**回归测评套件**。
> 本文档说明它能与什么对比、不能与什么对比，以及如何获得可对外对比的标准分数。

## 一、事实标准是什么

大模型测评领域**没有第三方认证机构**，"行业标准"实际由两部分构成：

1. **公开基准数据集**（事实上的通用语）：MMLU / MMLU-Pro、C-Eval / CMMLU（中文知识）、GSM8K / MATH（数学）、HumanEval / MBPP / EvalPlus（代码）、IFEval / IFBench（指令遵循）、LiveCodeBench（竞赛代码）、Arena-Hard / MT-Bench（LLM-as-judge）、SafetyBench / XSTest（安全与过度拒答）。
2. **通用测评框架**（决定分数怎么算）：**EleutherAI lm-evaluation-harness**（事实标准）、Stanford HELM、OpenAI Evals。

一个测评结果"可对外比较"，前提是：**同一基准数据集 + 同一评分代码 + 同一提示词/少样本设置 + 同一推理后端与精度**。缺任何一项，分数都不可直接比较。

## 二、本工具（model-eval）是什么、不是什么

| 项目 | 事实 |
| --- | --- |
| 题库来源 | **本工具自撰** 180 题，题型风格**参照** MMLU/C-Eval/GSM8K/HumanEval 范式 |
| 是否官方基准 | **否**。与上述任何公开基准**无对应关系**，题号、答案、难度分布均不同 |
| 分数含义 | 只能反映"在这 180 道自撰题上的表现"，**不是** MMLU 分、**不是** GSM8K 分 |
| 用途 | **回归监控**：固定题库下做 A/B（Q4 vs Q5、思考开/关、上下文长度、llama.cpp 版本、模型换版、量化对比） |

### 分数能与谁比较

- ✅ **能用本工具同一题库跑出来的任何结果**（同一数据集 SHA256，见报告第四节；本工具报告已内置哈希，可交叉核对）。
- ✅ **你自己的历史版本**（回归对比）。
- ❌ **不能**与任何公开榜单、官方 model card、第三方博客的分数比较。
- ❌ **不能**把本工具的"中文知识 82 分"写成"MMLU 82 分"。

## 三、想拿到可对外比较的分数：lm-evaluation-harness

行业事实标准做法是用 **lm-evaluation-harness** 直接打你的 llama.cpp 端点。官方 README 提供了专门的 `gguf` 后端（通过 llama-server 的 OpenAI 兼容接口评测）：

```bash
pip install lm_eval

# A. llama.cpp 专用后端（推荐；支持 generate_until + loglikelihood）
lm_eval --model gguf \
  --model_args base_url=http://<2080Ti设备IP>:8080,model=<模型别名> \
  --tasks mmlu,ceval-valid,gsm8k,humaneval \
  --batch_size 1

# B. 通用 OpenAI 兼容后端（适合 chat 类任务）
lm_eval --model local-chat-completions \
  --model_args model=<模型名>,base_url=http://<IP>:8080/v1 \
  --tasks mmlu,gsm8k,ifeval \
  --batch_size 1
```

已核实的事实（来源：lm-evaluation-harness 官方 README，检索于 2026-10-16）：

- `gguf` 后端要求 llama.cpp **2024-12 及更新**版本（返回现代 OpenAI 格式 `logprobs.content`），旧版 `token_logprobs` 不再支持。
- `gguf` 后端**不支持** `loglikelihood_rolling`，因此**不能跑 perplexity 类任务**（如 wikitext）。
- router 模式（多模型）需在 `--model_args` 里补 `model=<别名>`。
- 仓库内也提供 `scripts/run_lm_eval_baseline.sh` 一键脚本，已封装常用参数。

注意 `ceval-valid` / `mmlu` 等属于 loglikelihood 型任务，走 llama.cpp 时其实现是 teacher forcing 复现，与 HF 后端可能有量化噪声级差异——**报告分数时请写明用的是哪个后端**。

## 四、与"官方 model card 分数"的关系

Qwen3.8-27B（2026-08-14 发布，Apache 2.0，原生上下文 262,144）官方 model card 公布的是 **agentic/生产级基准**，不是本工具这类题库：

| 官方基准 | Qwen3.8-27B 官方分数 |
| --- | --- |
| Terminal-Bench 2.1（代理式终端操作） | 73.0 |
| LiveCodeBench v6（竞赛级编码） | 90.3 |
| IFBench（指令遵循） | 79.5 |
| SWE-bench Pro（代理式软件工程） | 61.7 |
| CoWorkBench（办公/代理协作） | 70.7 |

> 来源说明：以上数字取自两个独立二手来源对官方 model card 的转述（检索于 2026-10-16）；本次核验时 huggingface.co 在当前网络不可达，**未直接读取官方 README 原文**，正式引用前请自行核对官方 model card。

这几项基准都需要 **agent harness**（终端/仓库/办公环境）才能跑，**不是**把问题丢给 chat 接口就能测的；因此它们与本工具的分数**不可比**，也不适合在 2080Ti 单卡上做日常回归。想复现官方分数，需要额外的 agent 评测环境，成本远高于本工具。

## 五、即使跑标准基准，也要注意的三个坑

1. **数据污染**：GSM8K、MMLU 等公开基准几乎必然出现在模型的 post-training 数据中。Qwen3.8-27B 这类新模型的标准基准分数普遍偏乐观；严谨做法是补充 LiveCodeBench（持续更新、污染更小）、AIME/LiveBench 等较新基准。
2. **后端与精度差异**：官方分数通常用 vLLM/FP8 测得，你在 llama.cpp + GGUF Q4_K_M 上的分数天然偏低，**这属于正常差异而非模型变差**。做量化/后端对比时务必固定同一后端。
3. **提示词与少样本敏感**：MMLU 的 5-shot 与 0-shot 可差好几个点；本工具固定 temperature=0 + 零样本 + 固定模板，正是为了消掉这一层抖动。

## 六、推荐的双轨做法

| 目的 | 用什么 | 频率 |
| --- | --- | --- |
| 日常回归（换量化/换版本/调参数后确认没崩） | **本工具 model-eval**（秒级起、可断点续跑、零依赖） | 每次改动 |
| 对外汇报 / 与他人横向对比 | **lm-evaluation-harness** 标准任务（mmlu、ceval-valid、gsm8k、humaneval、ifeval） | 版本发布前 |
| 复现官方宣称能力 | 官方 model card 对应基准 + agent harness | 专项，需额外环境 |

本工具报告中已内置**数据集 SHA256 哈希**，任何一次结果都能证明"跑的是哪一版题库"，这是回归对比可信的基础。
